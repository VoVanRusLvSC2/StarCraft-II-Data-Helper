# Теоретическая модель и граница готовности — 2026-09-28

Этот документ отделяет реализованные механизмы от гипотез, которые ещё нельзя
использовать для автоматического удаления или переписывания данных. Проверки
редактором и полный повторный прогон отложены по просьбе пользователя. Слово
«теоретический» здесь не означает, что неизвестные правила SC2 стали известны.

## Что уже работает в коде

- Локальный граф объявлений хранит каталог, ID, исходный XML-адрес, уникальные
  class defaults, parent-цепочки и scalar provenance. Пустая строка, `0`,
  `false` и отсутствие значения не смешиваются в поддерживаемом subset.
- Декларации прямых и транзитивных зависимостей сохраняют порядок и источник.
  Явно заданные корни поиска/handle mappings позволяют найти архивы, проверить
  их хеши, прочитать активные GameData-компоненты и оставить их объявления в
  отдельных слоях. Пропуск, неоднозначность, цикл и нечитаемый источник
  диагностируются. Если архив содержит `Base.SC2Data/GameData.xml` с
  `<Includes><Catalog path="GameData/..."/>`, только перечисленные XML
  попадают в активный слой, в порядке списка; остальные показываются отдельно.
  Отсутствие manifest пока оставляет прежний режим обнаружения всех GameData
  XML и не является доказательством runtime-порядка.
- Для закрытого по файлам графа строится *гипотетический* порядок
  «зависимости перед потребителем». Индекс хранит все одноимённые объявления,
  не выбирая победителя. Probe экспортирует конфликтующие ID с исходными
  написаниями, точными местами и порядком. Без закрытого графа сохраняется
  порядок обнаружения, а не алфавитный порядок имён файлов.
- Повторяющиеся прямые и вложенные поля хранятся как raw declarations с
  ordinal, `index`, `removed`, наличием `value` и provenance. Неиндексированные
  повторы не схлопываются по имени поля.
- Поддерживаемые типизированные ссылки XML, GUI, Galaxy и текстовых Objects
  участвуют в анализе и установленных mutation paths. Нераспознанные carriers
  блокируют затронутые destructive-решения; post-merge проверка читает сырой
  выход для поддерживаемых XML/Objects случаев.
- Удаление, merge, rename и deep cleanup имеют существующие preflight,
  source/schema/settings revision и transaction guards. Массовый merge только
  по XML body hash выключен. Подробнее о доказанных subset — `ACCEPTANCE.md`.

## Что пока нельзя считать готовым даже теоретически

| Область | Текущее правило | Что нужно до разрешения `Safe` |
|---|---|---|
| Порядок активных include и слоёв | Manifest `Catalog` читается в dependency archive, найденные архивы имеют диагностический порядок; runtime winner не выбирается | Editor-saved fixture для порядка, override и include; проверка остальных форматов и локальных источников |
| Итоговые значения | Локальный scalar subset; конфликты слоёв дают Unknown | Доказанные default/override/parent/token правила между слоями, включая builtins |
| Массивы и структуры | Raw объявления без effective merge | Независимые примеры numeric/enum index, unindexed repeats, nested struct, removed/reset |
| Полнота ссылок | Проверенные фрагменты XML/GUI/Galaxy/Objects/Actor | Остальные грамматики, binary/external roots и точечные mutation spans |
| Применение | Существующие stale/rollback guards и частичный raw verifier | Полный dependency/config fingerprint на всех стадиях commit, независимый semantic verifier |
| Приёмка | Точечные Release-проверки текущего изменения; ранее полный Release/Debug 5/5 | Повторный полный Debug/Release, архив/папка, portable и Editor load/save/reopen/run |

`dependencyGraphComplete` и разрешение `Safe` **не** выводятся из
`dependencySourcesLocated` или `hypotheticalLayerOrder`. Если разрешения
зависимостей или правило композиции не доказаны, raw данные остаются доступны
для аудита, итоговое значение — Unknown. Это соответствует пункту 6 исходного
задания: неизвестное правило нельзя заменить догадкой ради «поддержки всего».

## Проверенное продолжение 2026-09-29

Один parser `GameDataIncludeManifest.h` теперь используется архивным и папочным
анализом. Папочный fixture включает один Catalog XML, исключает соседний XML,
оставляет его raw источник/ревизию и проверяет, что path traversal делает
анализ Partial без Safe. Folder/archive focused: 4/4 QtTest функций.

Полный текущий Release и Debug: по 5/5 CTest; core в каждой конфигурации:
175 passed, 0 failed, 4 skipped. В извлечённом `liberty.sc2mod` reference
snapshot (версия игры не установлена) read-only probe пометил 110 GameData XML
как неподключённые. Это свидетельство чтения настоящего manifest, но не
наблюдение итогового значения Editor.

Probe имеет версионированный JSON v2 с массивом причин Unknown и входными
SHA-256. Свежие копии Mercs/City прочитаны и JSON разобран PowerShell; обе
карты Partial, ноль Safe. Актуальный Release stage упакован и проверен вне
исходной папки: семь layout profiles PASS, packaged probe нашёл схему. В
headless smoke OpenGL context отсутствовал. Подробности —
`ACCEPTANCE_20260929.md`, `SUPPORTED_MODEL.md`, `PROBE_JSON_V2.md`.

Позднее Editor load/save/reopen был выполнен на отдельной копии Mercs;
gameplay, runtime winner и effective arrays не объявляются готовыми.

Архивный resolver дополнительно проверяет единственность совпадения путей
`DocumentInfo`, ComponentList, GameData manifest и каждого включённого Catalog
XML без учёта регистра. При двух вариантах имя не выбирается по порядку
перечисления; анализ остаётся неполным. Финальные после этого изменения
Release/Debug: по 5/5 CTest, core 176 passed / 0 failed / 4 skipped.

Отдельное наблюдение Editor 5.0.16.97563 подтвердило открытие копии Mercs:
отвечающее окно показывало имя карты, процесс закрыт, SHA-256 оригинала и
