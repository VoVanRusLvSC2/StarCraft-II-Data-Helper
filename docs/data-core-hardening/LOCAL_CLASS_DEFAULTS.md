﻿# Unique local class defaults - 2026-09-28

A failing regression showed that the active resolver indexed a `<CUnit default="1">` declaration but did not carry its typed WeaponArray.Link into a separate CUnit object's reference graph. The declaration was protected from ordinary unused deletion, yet its effect on that object's references was absent. The failing result is in `class-default-before.txt`.

`resolveCatalogReferences` now prepends exactly one local default declaration of the same class to each named object's conservative resolution chain. Typed links and tokens from that declaration are read in the descendant object's context, and the resulting edge retains an explicit `unique local class default typed link` explanation. The default declaration remains a separate DataNode with no ordinary object ID. If two defaults of the same class are present, the resolver does not select one by file order; it records an unresolved-layer diagnostic and emits no arbitrary inherited edge. The focused positive and negative regressions pass in `class-default-both.txt`.

This does not determine active component selection, cross-class XSD default inheritance, dependency/override order, or general scalar/array effective-value composition. The graph is intentionally conservative: a child override does not yet erase inherited reference edges. A link in a default is rewriteable only when its raw value has no token substitution; full source-span and output verification limits still apply. The previous core ZIP predates this step; the current defaults ZIP below contains it.
