﻿# Local scalar resolution contract (in progress)

The supported scope is a closed, local chain with one exact-class default at most and one declaration for each parent identity. A field is eligible only when the structural catalog index identifies a non-repeated scalar carrier. Source order among duplicate declarations and dependency layers is not inferred.

For each eligible field, the resolver will keep its raw XML spelling and a separate effective string, address, source declaration, resolution rule and state. Explicit empty, `0` and `false` are present values. No entry means that this local chain did not declare the field; it does not prove a runtime default or absence. A `removed` marker, duplicate scalar carrier, unresolved token, ambiguous parent/default or unsupported array composition yields Unknown for the affected address. Exact source paths and declaration locations are retained as provenance.

Deep cleanup may remove a child's scalar carrier only when the active model proves the child's effective value equals the unique local parent's value after removal, and no descendant could observe a changed token/inheritance context. Unsupported cases remain report-only. This contract does not establish cross-layer precedence, enum/numeric indexed array composition or Editor runtime semantics.

The first slice is implemented in the active `resolveCatalogReferences` pass and consumed by `DeepCleanupService` for duplicate child scalar nodes. A scalar `ResolvedValue` carries the original XML string, effective local string, field address, `DeclarationKey`, explanation, presence and known/unknown status. A unique local class default, unique parent chain and explicit local field overlay in that order. Repeated scalar carriers in one declaration and `removed` remain Unknown. The resolver does not create synthetic runtime values for fields absent from the local chain.

The failing-before test is `scalar-before.txt`. Focused after-fix checks cover explicit `0`, empty and `false`, inherited parent/default values, source location, the existing positive scalar cleanup, and Unknown for repeated/`removed` fields. The cleanup path now requires matching known local effective values and exact field provenance before proposing a scalar node as Safe. Typed links now carry the same exact source field/declaration coordinates. Root attributes are addressed by the later attribute checkpoint below; complete cleanup carrier coverage remains open.
