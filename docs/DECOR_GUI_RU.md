# Основная функция оптимизатора: декор и юниты ↔ Galaxy (4.0 Beta 2)

JSON/XML для восстановления по умолчанию не создаются. Настройка **Include
restore backup files (JSON/XML)** включает отдельную резервную копию и
сохраняется между запусками; в CLI это `--restore-sidecars`. Обычное обратное
преобразование читает размещения из Galaxy. В начале скрипта остаются компактные
служебные записи ID, флагов и отката каталога, без копии координат объектов.
`ActorData.xml` для размещения акторов нужен игре и не является резервной копией.
Из старых экспортов нельзя просто удалить `decor_import.xml`: их нужно заново
сгенерировать с новой настройкой.

При конвертации пары «тип актора / вариант» добавляются в штатный `Preload.xml`
карты. Вычисляемые вызовы `PreloadModel` в Galaxy не используются. Номера из
разметки сохраняются: вариант 7 в редакторе соответствует индексу 6, вариант 2 —
индексу 1. При экспорте только Galaxy нужно также импортировать сопутствующие
`Preload.xml` и данные акторов. Обратное восстановление возвращает исходный preload.

Объекты поверхности остаются исходными размещениями в карте: это типы
`TerrainObject*` и объекты с соответствующей категорией/связью в локальном
каталоге. Обычный декор, изображающий обрывы, рампы, мосты, платформы, дороги
или покрытия земли, переносится по обычным правилам — внешний вид не делает
его объектом поверхности. Связи с проходимостью проверяются отдельно. Рельефные файлы
не меняются; визуальный `ActorCreate` не заменяет нативную регистрацию объекта.
Прямые ссылки по ID/имени сохраняют исходные объекты. Штатные групповые команды
анимации/видимости/уничтожения по типу и области используют `ActorRegionSend`:
они могут обращаться к воссозданному декору с исходным ID типа и псевдонимом
`Doodad`. Поэтому такие команды сами по себе не исключают весь тип из переноса.
Неизвестные операции с типом декора в Galaxy консервативно сохраняют этот тип
в карте. Комментарии Galaxy ссылками не считаются.
Для вычисляемых имён типов и нестандартных скриптов используйте **Keep in map**.
Предпросмотр архивной карты применяет ту же проверку ссылок, что и экспорт.
В CLI можно явно сохранить декор через повторяемые `--keep-doodad-id <id>` и
`--keep-doodad-type <type>`.

Для дождя, тумана и освещения экспорт сохраняет различие между `NULL HDR`
(пользовательский цвет отключён) и явно заданным цветом. `NULL` передаётся
нативному сообщению без замены на белый; исходный HDR не обрезается.

1. Откройте копию карты `.SC2Map` в `SC2DataHelper.exe` и дождитесь анализа.
2. Во вкладке **Map Performance** найдите **Regions** по названию или ID и
   выберите их на карте или в списке. Выбранные области подсвечиваются и
   перечисляются над списком. Двойной щелчок по строке приближает область.
3. Имена функций берутся из имён выбранных регионов. Поле `Fallback function
   prefix` используется, если имя региона нельзя превратить в имя Galaxy.
4. Нажмите **Preview changes**. Проверьте список: `Remove from copy; recreate in Galaxy`
   означает перенос в код, а `Keep in Objects` — декорация останется на карте.
   Флажок **Keep in map** исключает выбранный декор или юнит из переноса.
5. Нажмите **Save converted map copy** и сохраните новый `.SC2Map`.
   Исходная карта не перезаписывается. Программа повторно проверит ссылки и
   может оставить в `Objects` больше декораций, чем показывал первичный обзор.
6. Откройте новую копию в StarCraft II Editor. В GUI-триггере используйте
   действие **Custom Script**, вызывающее показанные в Preview функции,
   например `Create_Map_1();` и `Clear_Map_1();` для региона `Map_1`.
   Проверьте компиляцию карты и поведение в игре.

Скрипт карты уже содержит `include "scripts/sc2dh_decor_opt"`. Если Editor
пересоздаст `MapScript.galaxy` и удалит эту строку, добавьте её один раз в
GUI-триггерах через Custom Script. Пишите путь **без** `.galaxy` в конце:
расширение Editor подставляет сам. Дублировать `include` не нужно.

Для каждого выбранного Region вызывается одна функция `Create_<имя региона>()`
без `Batch_*` и без ожиданий `Wait`: она создаёт перенесённый декор и юниты.
Внутри скрипта большой объём кода разбит на короткие служебные функции
`DecorOpt_CreatePart_*`, чтобы компилятор Galaxy не упирался в предел перехода.
Galaxy-код восстанавливает вариант модели, цвет команды, положение, поворот,
масштаб и оттенок. Флаги редактора `HeightOffset` и `ForcePlacement` сами по
себе не мешают переносу. Объекты с игровым footprint/pathing, неизвестными
полями размещения и прямыми ссылками остаются в `Objects`; Preview показывает
причину. Для применения параметров используется актор, возвращённый самим
`ActorCreate`; создание дочерних акторов не меняет адресата. Координаты, поворот, масштаб и вариант
модели. Старые оптимизированные копии нужно создать заново; одна замена EXE
уже созданную карту не исправит. Визуальное совпадение нужно проверить в
Editor и в игре.
Углы `Rotation`, `Pitch`, `Roll` переводятся из радиан `Objects` в векторы
направления и верха модели для штатного `SetRotation`, включая нулевой поворот.
Новый экспорт также сохраняет исходные числовые записи углов в строковом
параметре каждого вызова создания. У декора это четвёртое слово трансформации
`Rotation,Pitch,Roll`, у юнита — радианы после расчётного направления в градусах.
Знак `~` обозначает отсутствовавший атрибут с нулевым значением по умолчанию.
Обратное восстановление проверяет согласованность исходных углов с расчётными
значениями и возвращает исходную запись без тригонометрического пересчёта.
Несогласованные данные отклоняются. Векторы поворота выводятся с полной
точностью double; у старых экспортов без исходных углов остаётся прежний
путь обратного вычисления с его округлением. Проверка точности восстановленной
карты не означает, что числовые типы движка имеют неограниченную точность.
Полный поворот по трём осям задаётся источнику размещения до создания модели
и самой возвращённой модели после создания; сложный наклон не зависит только
от передачи трансформации через `CopySource`.
Размещённый декор использует оси модели, а обработчик сообщения считает
направлением локальную ось -Y. Прямое применение формулы `MakeModelFaceAngle`
добавляло к модели лишние 90°. Перевод учитывает эту разницу, а проверка
восстанавливает фактический базис сообщения и сравнивает его с поворотом
загрузчика размещённого декора. Вариант модели 0
тоже задаётся явно. Анимации запускает исходный актор по игровому каталогу карты,
включая наследование, макросы событий, глобальные циклы и настройки модели.
Экспорт не подменяет это поведение анимацией предпросмотра `EditorAnim` и не
навязывает общий `Stand`. Модель и её вариант передаются первыми двумя параметрами
содержимого `ActorCreate` до инициализации модели. Для моделей с вариантами
дополнительно отправляется `ModelSwap` с сохранённым индексом: один параметр
создания не обеспечивал выбор нужного варианта. Для обычных моделей с одним
вариантом и индексом 0 замена не выполняется.
У размещённого декора координаты и поворот заданы до вычисления области тумана
войны. Старый экспорт создавал актор в начале координат, а затем переносил модель:
сохранённая область тумана оставалась в начале координат и могла останавливать
анимации и частицы, даже когда сама модель уже видна игроку.
Теперь конвертация добавляет в `ActorData.xml` служебный site-актор и поля
`CopySource` для экспортируемых типов декора. Они получают положение и поворот
от заранее размещённого site-актора до завершения создания декора. Имена типов
остаются исходными: ссылки `##id##`, звуки и события не получают другое имя.
Настройки анимации и тумана не переопределяются. Очистка региона удаляет весь
контекст вместе с дочерними акторами. Galaxy-файл требует этих полей в копии
карты: переноса одного скрипта недостаточно.
Обратное преобразование возвращает исходный `ActorData.xml` точно по байтам
или удаляет служебный каталог, если его не было в оригинале. Правки каталога,
сделанные после экспорта, защищены от перезаписи.
`Stand`, `Stand 01` и `Stand 02` — клипы анимации модели, а не варианты размещения
декора. Их выбор остаётся за исходным актором. Новый путь применяется ко всем
экспортируемым типам; движение флюгера и снега в игре ещё нужно проверить.
Данные зависимостей и пользовательских модов разрешает сама игра; локальный кеш
не становится обязательной частью экспортированной карты. Повторного запуска
всех событий создания нет: он мог бы дублировать звуки и дочерние акторы.
Случайная фаза анимации может отличаться от исходной карты. Проверка
«конвертировать → восстановить» сверяет сохранённые данные размещения, но
не выполняет Galaxy и сама по себе не доказывает совпадение изображения в игре.
Кнопка **Choose units to keep in Objects...** открывает окно с поиском по
юнитам. Можно отметить один юнит или весь его тип: отмеченные юниты останутся
в `Objects`. Уже защищённые правилами безопасности юниты помечены **Already
kept**. В CLI доступны повторяемые параметры `--keep-unit-id <id>` и
`--keep-unit-type <type>`.

Новые копии, созданные SC2DataHelper, содержат сжатые данные для точного
возврата. Откройте такую копию и нажмите **Restore original placements**:
программа создаст отдельную карту с исходными `Objects` и
`MapScript.galaxy`. Аналог в CLI: `SC2DecorOptimizeMap <конвертированная карта>
<новая карта> --restore`. Если после экспорта менялись Galaxy, `Objects` или
`MapScript.galaxy`, восстановление остановится, чтобы не потерять правки.
Старые копии без данных восстановления этим способом вернуть нельзя.
Если регионы перекрываются, объект относится к меньшей по площади области.
Юниты с единственным флагом `ForcePlacement` создаются с игнорированием
ограничений размещения; юниты с другими неподдерживаемыми флагами остаются
в `Objects`, а причина показывается в Preview.
В JSON-отчёте CLI причины перечислены в `unitSafetyReasons` и `keptUnits`.
Галочки **Keep in map** в Preview позволяют оставить отдельные объекты в
`Objects`. Юнит переносится только при поддерживаемых свойствах и отсутствии
прямых ссылок на его ID/имя в триггерах и скриптах. Общие действия вида
«все юниты в регионе» **не считаются прямой ссылкой**: до вызова `Create` такой
триггер увидит меньше юнитов, после `Clear` они снова исчезнут. Это нужно
проверить в Editor и игре на конкретной карте.

Переносятся только поддерживаемые декорации без блокирующих ссылок. Структурная
проверка новой карты не заменяет проверку Galaxy в Editor. Вкладка **Unused Data
Objects** отдельно удаляет только доказанно неиспользуемые объекты каталога;
она не удаляет размещённые декорации.

Разбор чисел проверяет значение целиком: поддерживаются `.5`, `1.` и `1e-3`,
но посторонний текст, неверные разделители и бесконечные значения не принимаются.
Неизвестные, повторяющиеся и противоречивые поля старого формата сохраняют
объект в `Objects`. Индекс варианта 255 (случайный выбор) также остаётся исходным.
Номер игрока для владельца или TeamColor должен быть в диапазоне 0–15.
TeamColor разрешается через цвет указанного игрока, отдельно для diffuse и emissive.
Значения, не помещающиеся в числовые параметры Galaxy, остаются в `Objects`:
тип [fixed](https://sc2mapster.wiki.gg/wiki/Types/Fixed) имеет 12 дробных битов.
Это защита от потерь при преобразовании, а не заявление о поддержке любых
свойств любого мода. Проверка всех размещений конкретной карты и визуальная
проверка выполнения Galaxy в игре — отдельные этапы.
